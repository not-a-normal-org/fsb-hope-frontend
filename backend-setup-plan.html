System Overview

Database + Auth + Admin

Supabase handles your database, user auth, and row-level security. Supabase Studio is your raw admin panel.

Payments + Subscriptions

Stripe handles all money. Subscriptions, one-off payments, invoices, refunds, and customer portal. Zero billing UI to build.

Custom Admin Panel

A /admin dashboard inside your Next.js app. Your branded view for customers, orders, newsletters, and products.

Build the Supabase Database Schema
Go to Supabase > SQL Editor and run this SQL
supabase sql editor — run this entire block
-- Enable UUID extension
create extension if not exists "uuid-ossp";

-- PRODUCTS TABLE
create table products (
  id uuid default uuid_generate_v4() primary key,
  stripe_product_id text unique not null,
  stripe_price_id text unique not null,
  name text not null,
  description text,
  type text check (type in ('subscription', 'one_off')) not null,
  price_cents integer not null,
  currency text default 'aud',
  billing_interval text check (billing_interval in ('month', 'year', null)),
  features jsonb default '[]',
  is_active boolean default true,
  sort_order integer default 0,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- CUSTOMERS TABLE
create table customers (
  id uuid default uuid_generate_v4() primary key,
  user_id uuid references auth.users(id) on delete cascade,
  stripe_customer_id text unique,
  email text not null,
  full_name text,
  phone text,
  company_name text,
  business_type text,
  annual_spend_range text,
  abn text,
  address jsonb,
  notes text,
  tags text[] default '{}',
  status text check (status in ('active', 'inactive', 'blocked', 'pending')) default 'pending',
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- SUBSCRIPTIONS TABLE
create table subscriptions (
  id uuid default uuid_generate_v4() primary key,
  customer_id uuid references customers(id) on delete cascade,
  stripe_subscription_id text unique,
  stripe_price_id text not null,
  product_id uuid references products(id),
  status text check (status in ('active', 'canceled', 'past_due', 'trialing', 'incomplete', 'paused')) not null,
  current_period_start timestamptz,
  current_period_end timestamptz,
  cancel_at_period_end boolean default false,
  canceled_at timestamptz,
  trial_end timestamptz,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- ORDERS TABLE (one-off payments like Concierge)
create table orders (
  id uuid default uuid_generate_v4() primary key,
  customer_id uuid references customers(id) on delete set null,
  stripe_payment_intent_id text unique,
  stripe_session_id text unique,
  product_id uuid references products(id),
  amount_cents integer not null,
  currency text default 'aud',
  status text check (status in ('pending', 'paid', 'refunded', 'failed')) default 'pending',
  metadata jsonb default '{}',
  notes text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

-- NEWSLETTER SUBSCRIBERS TABLE
create table newsletter_subscribers (
  id uuid default uuid_generate_v4() primary key,
  email text unique not null,
  full_name text,
  source text,
  is_active boolean default true,
  subscribed_at timestamptz default now(),
  unsubscribed_at timestamptz
);

-- APPOINTMENTS TABLE
create table appointments (
  id uuid default uuid_generate_v4() primary key,
  customer_id uuid references customers(id) on delete set null,
  cal_booking_id text unique,
  event_type text,
  title text,
  attendee_name text,
  attendee_email text,
  attendee_phone text,
  start_time timestamptz,
  end_time timestamptz,
  status text check (status in ('upcoming', 'completed', 'cancelled', 'no_show')) default 'upcoming',
  notes text,
  metadata jsonb default '{}',
  created_at timestamptz default now()
);

-- ADMIN AUDIT LOG
create table admin_audit_log (
  id uuid default uuid_generate_v4() primary key,
  admin_user text,
  action text not null,
  table_name text,
  record_id text,
  old_value jsonb,
  new_value jsonb,
  created_at timestamptz default now()
);

-- AUTO-UPDATE updated_at
create or replace function update_updated_at()
returns trigger as $$
begin
  new.updated_at = now();
  return new;
end;
$$ language plpgsql;

create trigger update_customers_updated_at
  before update on customers for each row execute function update_updated_at();
create trigger update_subscriptions_updated_at
  before update on subscriptions for each row execute function update_updated_at();
create trigger update_products_updated_at
  before update on products for each row execute function update_updated_at();
create trigger update_orders_updated_at
  before update on orders for each row execute function update_updated_at();

-- ROW LEVEL SECURITY
alter table customers enable row level security;
alter table subscriptions enable row level security;
alter table orders enable row level security;
alter table newsletter_subscribers enable row level security;
alter table appointments enable row level security;
alter table products enable row level security;

-- Policies
create policy "Public can view active products"
  on products for select using (is_active = true);

create policy "Customers see own data"
  on customers for select using (auth.uid() = user_id);

create policy "Customers see own subscriptions"
  on subscriptions for select using (
    customer_id in (select id from customers where user_id = auth.uid())
  );

create policy "Customers see own orders"
  on orders for select using (
    customer_id in (select id from customers where user_id = auth.uid())
  );

CP 3
Create the Stripe Webhook Handler
The most important file — keeps your DB in sync with Stripe
Copilot Prompt 3 — paste this exactly
Create src/app/api/webhooks/stripe/route.ts in my Next.js 14 App Router project.

This is a POST route handler for Stripe webhooks.

It must:
1. Read the raw request body as text (not JSON) — required for Stripe signature verification
2. Get the stripe-signature header from the request
3. Verify the webhook using:
   stripe.webhooks.constructEvent(body, signature, process.env.STRIPE_WEBHOOK_SECRET!)
4. Use supabaseAdmin (from src/lib/supabase/admin.ts) for all DB operations

Handle these Stripe events:

checkout.session.completed
- Get the session with customer and subscription/payment_intent expanded
- If mode is 'subscription':
  - Upsert a row in customers: stripe_customer_id, email from session.customer_details.email
  - Insert a row in subscriptions: stripe_subscription_id, stripe_price_id, status, period dates
- If mode is 'payment':
  - Upsert a row in customers
  - Insert a row in orders: stripe_payment_intent_id, stripe_session_id, amount_cents, status 'paid'

customer.subscription.updated
- Find subscription by stripe_subscription_id
- Update: status, current_period_start, current_period_end, cancel_at_period_end

customer.subscription.deleted
- Find subscription by stripe_subscription_id
- Update status to 'canceled', set canceled_at to now()

invoice.paid
- Find customer by stripe_customer_id
- Update subscription status to 'active' if it was 'past_due'

invoice.payment_failed
- Find subscription by stripe_customer_id
- Update subscription status to 'past_due'

Return 200 for handled events, 400 for signature failures, 200 for unhandled events.
TypeScript throughout. Wrap everything in try/catch with console.error logging.

  2. Connect the repo to Vercel (vercel.com > New Project)
  3. Add all env variables from .env.local to Vercel > Settings > Environment Variables
  4. Deploy
  5. Once deployed, go to Stripe > Developers > Webhooks > Add endpoint:
    stripe webhook url
    https://yoursite.vercel.app/api/webhooks/stripe
  6. Add all 5 webhook events from Step 3
  7. Copy the signing secret into Vercel as STRIPE_WEBHOOK_SECRET
  8. Trigger a Vercel redeploy to pick up the new variable
Test with Stripe's webhook CLI locally before going live: stripe listen --forward-to localhost:3000/api/webhooks/stripe

Adding a New Product Later

  1. Create the product and price in Stripe Dashboard
  2. Copy the new Price ID
  3. Add a row in your Supabase products table using your admin panel
  4. Add a <CheckoutButton priceId="..." /> anywhere on the site
  5. Done — no other code changes needed
